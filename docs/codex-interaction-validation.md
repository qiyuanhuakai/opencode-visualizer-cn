# Codex 协作模式与线程目标交互验证

验证日期：2026-09-09。环境：Node 24.14.1、Vis 开发服务、vis_bridge、Codex app-server 0.153.4。

## 使用方式

- 消息输入区的 Codex 协作模式默认选择 `default`，即使服务端先返回 Plan，也不会让新线程默认进入 Plan。已有草稿中的主动选择仍保留。
- 输入区思考强度右侧显示线程目标长条。未设置时显示“设置线程目标”，设置后显示目标摘要；长文本省略显示，悬停可查看全文。
- 点击长条打开独立“线程目标”悬浮窗，可修改目标、状态和可选 token 预算，也可清除目标。窗口打开后切换线程时，编辑器跟随当前线程。
- 保存目标本身不会发送消息或启动一轮执行。预算留空表示不设预算，填写时必须是正整数；目标最多 4,000 字符。
- 协作模式列表位于 Codex 工具菜单中，可直接选择模式，选择同步至输入区并在下一条消息生效。工具菜单开关位于设置的实验性功能页；输入区目标入口不依赖该开关。

## 已修复的问题

- 新线程的通用 agent 默认逻辑误将 Codex 列表第一项 Plan 作为默认模式。
- 协作模式面板只能查看，无法选择；列表读取失败与空列表没有区分。
- 清空预算会提交空字符串，零、负数和小数未被阻止。
- 目标保存、清除和读取失败缺少可见反馈；断线、未选线程、未开放能力缺少就近说明。
- 当前线程没有消费目标更新和清除通知。新增通知归属校验与读取代际隔离，避免旧响应覆盖新目标。
- 线程切换及断线重连时，旧编辑操作的完成提示可能污染新上下文。

## 验证边界

- 未进行长时间自主目标执行、真实预算耗尽或真实用户可用性访谈；这里验证的是目标管理、状态同步、消息模式传递和界面操作。
- 既有桌面导航在手机宽度下仍有局部截断；375px 的目标条和窗口检查采用侧栏收起状态。
- 构建仍提示已有大块文件；InputPanel ACP 测试退出阶段出现 worker 终止超时提示，但全部断言通过且命令退出码为 0。
